# taoFPGA Dataflow — 3D architecture walkthrough

Interactive WebGL walkthrough of the transformer accelerator: the physical
Zynq-7020 floorplan, the logical PS7 → DMA → 24×24 systolic array → DMA
pipeline, a ghosted Softmax/GELU extension, a guided "how it works" tour, and
live throughput telemetry. All numbers are extracted from the routed Vivado
checkpoint by [`scripts/dump_arch.tcl`](../scripts/dump_arch.tcl).

## Files

| | |
|---|---|
| **`taofpga_dataflow.html`** | The deliverable — one self-contained file, no server, works offline. **Generated by `build.py`; do not hand-edit.** |
| `src/index.html` | Page shell + markup |
| `src/style.css` | All styling |
| `src/data.js` | Extracted hardware facts (`CRO DEV N EDGES ACC GHOST`) — regenerate from `exports/architecture_data*.json` |
| `src/content.js` | Guided-tour script (`STAGES`) — edit the copy here |
| `src/app.js` | Scene construction, animation, UI |
| `src/lib/` | Vendored three.js r128 modules (r128 core + post-processing + controls) |

`data.js` and `content.js` define globals that `app.js` closes over; they load
as three ordered `<script>` tags. There is no bundler and no build step for
development.

## Develop

Open `src/index.html` directly in a browser (or `python -m http.server` from
`src/` if your browser blocks `file://` module loads). Edit `style.css`,
`content.js`, `data.js`, or `app.js` and refresh.

## Build the single file

```sh
python viz/build.py            # writes viz/taofpga_dataflow.html
python viz/build.py --check    # exit 1 if the bundle is stale (used by CI)
```

`build.py` inlines `style.css`, `src/lib/*.js`, and the three app scripts into
`index.html`. The Google Fonts `<link>` is left external on purpose — it
enhances when online and falls back to system fonts offline. No dependencies
beyond the Python standard library.

## CI

`viz/ci/build-viz.yml` is a GitHub Actions workflow that checks the bundle on
PRs and rebuilds + commits it on push to `master`. It ships here rather than in
`.github/workflows/` because that path needs a token with the `workflow` scope
to push. To enable it:

```sh
mkdir -p .github/workflows
git mv viz/ci/build-viz.yml .github/workflows/build-viz.yml
git commit -m "ci: enable build-viz workflow" && git push
```

(or paste its contents into the repo's **Actions → new workflow** page on
github.com).
